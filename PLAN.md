## 2. Architecture

```
Browser ──► Next.js (App Router, TypeScript, Tailwind CSS)
              ├─ Static/SSG pages (portfolio + project details)
              ├─ /api/chat    ──► embed query ──► cosine search over local JSON vector store
              │                     └─► grounded prompt ──► LLM API (server-side key only)
              └─ /api/contact ──► validate + honeypot ──► log/accept (no external mail service by default)

Offline ingest (npm run ingest):
  data/knowledge/*.md  ──► chunk (heading-aware, ~500 chars, overlap) ──► embeddings API
                       ──► data/vector-store.json (chunks + vectors + metadata)
```

**Why this shape:** simplest reliable architecture per requirements — one deployable (Vercel), no separate backend, no external vector DB. The vector store is a local JSON file committed/generated at ingest time; cosine similarity in-process is more than fast enough for a CV-sized corpus.

### RAG pipeline
- **Knowledge base:** CV content transcribed into Markdown files under `data/knowledge/` (`profile.md`, `skills.md`, `projects.md`, `experience.md`, `education.md`, `certifications.md`), each chunk carrying `source` metadata (CV section name) for citations.
- **Ingest:** `scripts/ingest.ts` — reads Markdown, splits into chunks, calls the embedding provider, writes `data/vector-store.json`.
- **Retrieval:** query embedded with the same model; cosine similarity; top-k = 4; results passed as context.
- **Generation:** system prompt enforces strict grounding — answer only from retrieved context, never invent skills/experience/certifications, say "that information is not available in the provided documents" when missing, cite the CV section.
- **Provider config (env-driven):** `LLM_PROVIDER` / `EMBEDDING_PROVIDER` default to OpenAI; base URL + model names are configurable so an OpenAI-compatible provider can be swapped in without code changes.
- **Fallback:** if no API key is configured, `/api/chat` returns a clear, readable error explaining the assistant is not configured yet (no crash, no fabricated answers). A keyword-based local retrieval fallback is included for demo/testing without keys.
- **Security:** keys only in server env vars, never in client code; input validation (length, role checks); in-memory rate limit ≈ 20 req/min/IP on `/api/chat`; system prompt protected (refuse to reveal it); knowledge base limited to user-approved documents.

### Chat UI
Floating button (bottom-right), panel with welcome message + suggested recruiter questions, conversation history sent for follow-ups, loading indicator, readable errors, clear-chat button, mobile-friendly, openable from the hero button (custom event).

## 3. API Keys, Services & Costs

| Service | Required? | Cost |
|---|---|---|
| OpenAI API (embeddings `text-embedding-3-small` + chat model e.g. `gpt-4o-mini`) | Yes, for live chatbot | Pay-as-you-go. Embeddings for a CV are effectively < $0.01 one-off. Chat ≈ $0.15 / 1M input tokens (gpt-4o-mini list price at time of writing) — a recruiter chat costs a fraction of a cent per message. |
| Vercel (hosting) | Recommended for deployment | Hobby tier free; sufficient for this site. |
| PostgreSQL/pgvector, Pinecone, etc. | **No** — deliberately not used | $0 (local JSON vector store). |
| Domain name | Optional | ~$10–15/yr if a custom domain is wanted. |

No other paid services. Everything else (Next.js, Tailwind, Vitest) is open source.
